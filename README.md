# FugScope для Resolume 7 / Apple Silicon

## Цель
Запрос пользователя: «Создай копию плагина fugscope для resolume 7 под мак arm».
Подготовить реализацию совместимого по назначению плагина для Resolume 7 на macOS ARM64, с исходниками, инструкцией сборки и установки и доступными проверками.

## Исходные данные и ограничения
- Известны название FugScope, хост Resolume 7 и архитектура Apple Silicon.
- Пользователь подтвердил Resolume 7.16; журнал использует папку Resolume Arena.
  Patch-версия и архитектура процесса не уточнены. Оригинал FugScope изучен
  по публичным исходникам.
- Рабочая среда агента Linux, Mac и Resolume недоступны. Пользователь собирает
  проект у себя на Mac и передал лог компиляции.
- Все материалы задачи хранятся в этой директории. Документация на русском.

## Статус на 2026-09-06
Создан исходный порт FugScope ARM на FFGL 2.2 / OpenGL 4.1 Core.
Код, зависимости, тесты, macOS-скрипты сборки/установки и документация собраны в
`FugScopeArm/`. Актуальный дистрибутив: `FugScopeArm-source-diagnostics.zip`.
Архив `FugScopeArm-source-fix1.zip` содержит исправление lipo, но ещё не содержит
явного шага добавления FFGL-каталога и диагностического скрипта.
`FugScopeArm-source.zip` — первоначальный архив, оставлен как история; в нём
ошибка порядка аргументов `lipo`.
**По присланному пользователем логу компиляция и линковка на Mac прошли, затем
скрипт остановился на lipo. Порядок аргументов исправлен. Позже пользователь
подтвердил наличие сообщения «Установлено»; обнаружение и запуск в Resolume
по-прежнему не подтверждены. Вывод отдельных проверок Mac не получен.**
В рабочей среде агента готового macOS bundle нет.
Источник отсутствует в Sources. Пользователь прислал журнал от 2026-09-06
22:17:38 +03:00: Resolume сканирует `/Users/ivan/Documents/Resolume/Extra Effects`,
находит `FugScopeArm.bundle/Contents/MacOS/FugScopeArm`, затем сообщает
`Loading plugin failed, lib could not be opened.` Загружено 0 плагинов.
**Путь сканирования подтверждён; больше не предлагать повторно добавлять папку.**
Подробная ошибка загрузчика и архитектура процесса пока неизвестны. Нельзя
выдавать Rosetta, подпись или зависимость за установленную причину.

## План
1. Проверить происхождение и возможности FugScope, доступность исходников и условия лицензии.
2. Уточнить FFGL/API и требования Apple Silicon в Resolume 7.
3. Реализовать плагин и подготовить воспроизводимую сборку под macOS ARM64.
4. Выполнить доступные проверки, документировать ограничения и оставшиеся шаги.

## Сделано и принятые решения
- Найден оригинал https://github.com/bigfug/Freeframe, GPL-3.0; commit
  `cbecd9e4dd0fa148a2cb33ebbd19822bde15c247`.
- Сохранены 7 режимов Config, 3 Arrange, Scale 0–10, Width 1–50,
  signed-max resampling 1024 mono samples с первого системного входа.
- Порт имеет отдельные имя FugScope ARM и ID FSAR, поэтому не подменяет BF24
  и не мигрирует старые композиции автоматически.
- Legacy OpenGL заменён GLSL 4.10, VAO/VBO и треугольниками. Толстые линии и
  заливки исправлены; пиксельная идентичность старой реализации не обещается.
- Исправлены гонка аудиобуфера, null input и нечётные размеры. Добавлен Test Signal.
- Vendored официальный FFGL SDK и PortAudio 19.7.0 (CoreAudio), лицензии сохранены.
- Подготовлены ARM64/Universal сборка через xcrun без Homebrew/CMake,
  локальная подпись, установка с резервной копией прежней версии, GitHub Actions
  workflow (не запускался и никуда не публиковался).
- Выполнены ASan/UBSan core/audio tests и 21 реальная отрисовка через FFGL
  на Mesa OpenGL 4.1 Core; проверены metadata, GL state, resize, прозрачность.
  LeakSanitizer отключён из-за ptrace; микрофон/CoreAudio не проверялись.
- Предпросмотр `FugScopeArm/preview.png` визуально проверен.
- После лога пользователя исправлена команда проверки архитектуры:
  `xcrun lipo <бинарник> -verify_arch <архитектуры>`. Предыдущая форма помещала
  путь после списка архитектур; lipo принимал путь за ещё одну архитектуру.
  Предупреждения int → float не являлись причиной остановки. Исходники
  плагина и зависимости оставлены без изменений.
- В инструкцию добавлены команды для проверки, подписи и установки уже
  собранного bundle без повторной компиляции. Обновлённый ZIP и shell syntax
  проверены; реального запуска lipo/codesign в среде агента не было.
- После сообщения об отсутствии Sources проверена регистрация FF_SOURCE и
  руководство хоста. README SDK использует `Documents/Resolume/Extra Effects`,
  руководство — `Documents/Resolume Arena` / `Resolume Avenue`. В установщик
  и инструкцию добавлен явный шаг регистрации папки в Video → FFGL Plugin
  Directories. Это возможная причина, не установленный диагноз.
- Добавлен `FugScopeArm/Diagnose FugScope.command`: read-only проверка bundle,
  архитектуры, подписи, exports, зависимостей и ограниченных строк журналов.
  Отчёт сохраняется рядом со скриптом в `FugScope-Diagnostics`; не отправляется
  автоматически. Shell syntax/архив проверены, Mac-исполнение не проверено.
- После нового журнала диагностический скрипт расширен: компилирует небольшой
  C helper `dlopen`/`dlerror` с `-arch arm64`, проверяет установленную библиотеку
  и наличие `plugMain` в отдельном процессе, без аудиозахвата и рендеринга.
  Отдельный пакет для пользователя: `FugScope-Load-Check.zip`. Он содержит
  только актуальный Diagnose FugScope.command, без пересборки плагина.
  Старый полный source-diagnostics архив содержит предыдущую диагностику.
  Успех helper не доказывает загрузку в Resolume: его архитектура и политика
  подписи могут отличаться. Настройки, quarantine и подписи не изменяются.

## Следующий шаг для другого агента
Получить вывод актуального Diagnose FugScope.command из FugScope-Load-Check.zip:
file/lipo, codesign, зависимости и особенно DLOPEN ERROR либо DLOPEN OK.
При DLOPEN OK определить Kind процесса Resolume Apple/Intel и, если нативный,
исследовать различия загрузчика/политики host. Версия 7.16, наличие сообщения
установки, сканирование папки и наличие файла уже подтверждены; не спрашивать
их снова. Исправлять следующую причину по детальному выводу загрузчика.
Затем проверить bundle в Resolume 7.11+ нативно. По результату
обновить Markdown и выдать проверенный bundle вместе с соответствующими исходниками.
Не выдавать Linux `.so` за плагин для Mac и не называть macOS-проверку пройденной.
