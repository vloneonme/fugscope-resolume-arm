# Выпуск готовых сборок

Пользователь скачивает ZIP из GitHub Releases по ссылке в README, распаковывает и копирует плагин. Учётная запись GitHub и инструменты сборки не нужны. CI artifacts предназначены для разработки.

## Процесс сопровождающего

1. Обновить версии в CMakeLists.txt, resources/Info.plist и метаданных плагина при изменении версии кода. Добавить `docs/releases/vX.Y.Z.md` с изменениями и границами проверок.
2. Закоммитить и отправить изменения в main. Создать аннотированный тег `vX.Y.Z` на выбранном коммите и отправить тег в origin. Тег опубликованного релиза не переносить.
3. `release.yml` вызывает те же Windows/macOS/Linux проверки, которые используются в CI. Только при успехе всех трёх jobs создаётся draft release, загружаются два бинарных ZIP, полный source ZIP и SHA-256, затем релиз публикуется.
4. Проверить страницу релиза и скачивание архивов. Имена файлов стабильные; README использует `/releases/latest/download/…`.

Права `contents: write` есть только у publishing job. GitHub token передаётся через окружение этого job. Готовый публичный релиз workflow не перезаписывает; неудавшуюся загрузку draft можно повторить через rerun. Бинарники не хранятся в Git, соответствующие исходники публикуются вместе с ними.

## Текущее состояние

Подготовлен первый выпуск v1.0.0: код плагина не изменён, добавлены автоматическая публикация и прямые ссылки. Следующий шаг — проверить опубликованные assets после выполнения workflow. Ограничения проверки хоста и подписи указаны в README и release notes.
